# Матрица состояний

Всё, что интерфейс умеет показывать. Чек-лист для редизайна: каждое из этих
состояний должно получить своё решение, иначе оно всплывёт на демо.

## Форма запуска (сайдбар)

| Состояние | Чем вызвано | Как выглядит сейчас | Кадр |
| --- | --- | --- | --- |
| Исходное | первый заход | «ЗАПУСТИТЬ» заблокирован, под кнопками caption «Сначала выполните проверку конфигурации» | [02](../01-screens/02-sidebar-default.png) |
| Нет ключа провайдера | `OPENROUTER_API_KEY` не задан | серый блок «Настройте ключи: …» | [02](../01-screens/02-sidebar-default.png) |
| CUS невалидны | совпадают или не цифры | второй серый блок над первым, визуально одинаковые | [14](../01-screens/14-form-validation-error.png) |
| Preflight не пройден | 1+ blocking check упал | expander «Проверка · 3/5» раскрыт, запуск заблокирован | [11](../01-screens/11-preflight-failed-sidebar.png) |
| Preflight пройден | все проверки ok | expander свёрнут, «ЗАПУСТИТЬ» активен | [33](../01-screens/33-component-preflight-pass.png) |
| Конфигурация изменилась после проверки | fingerprint не совпал | запуск снова заблокирован, `run_error` в основной области | — |
| Контекст цели не заполнен | Adaptive BAC без arch/system card | expander раскрывается принудительно, две ошибки внутри | [08](../01-screens/08-sidebar-target-context.png) |
| Идёт прогон | `run_in_progress` | форма остаётся активной, блокировки нет | [29](../01-screens/29-runtime-only-states.png) |

Fingerprint конфигурации (`_config_fingerprint`, строка 677) считается по
моделям, CUS, числу попыток, режиму авторизации, сценарию и хешу
`config/target.yaml`. Любое изменение обнуляет право на запуск.

## Основная область

| Состояние | Чем вызвано | Как выглядит сейчас | Кадр |
| --- | --- | --- | --- |
| Пусто | нет `last_result` | одна серая плашка «Проверьте конфигурацию и запустите сценарий» | [03](../01-screens/03-main-empty-state.png) |
| Идёт прогон | `run_pipeline` шлёт события | прогресс-бар с текстом + до 6 строк живого лога | [29](../01-screens/29-runtime-only-states.png) |
| Прогон завершён | `status="completed"` | `st.success` с run id, затем вкладки | [17c](../01-screens/17c-result-compromised-tall.png) |
| Прогон упал | `PipelineRunError` | `st.error` с sanitized-текстом, частичные evidence сохранены | [17](../01-screens/17-result-incomplete-tall.png) |
| Конфигурация не читается | битый `target.yaml` | `st.error` вместо всего интерфейса, остаётся только история | — |
| Результат в неверном формате | битый `last_result` | `st.error` «Сохранённый результат имеет неверный формат» | — |

## Вердикт прогона

Четыре значения, вычисляются в `_render_outcome_summary` (строка 431).
Сейчас все четыре набираются одним шрифтом одного цвета — отличается
только текст.

| Вердикт | Условие | Что показано |
| --- | --- | --- |
| `COMPROMISED` | есть хотя бы один `proven` | ASR, N/M, evidence, COMPLETED | [19](../01-screens/19-component-result-summary.png) |
| `NOT PROVEN` | оценённые попытки есть, `proven` нет | то же, полоса доли пустая | — |
| `INCOMPLETE` | статус `failed` или `interrupted` | ASR = N/A, статус FAILED | [17b](../01-screens/17b-component-result-summary-incomplete.png) |
| `NOT SCORED` | ни одной оценённой попытки | ASR = N/A, 0/0 | — |

Вердикт отдельной попытки: `proven`, `not_proven`, `invalid` — выводится
только заглавными буквами в таблице попыток, без цвета и без иконки.

## История запусков

| Состояние | Как выглядит |
| --- | --- |
| Прогонов нет | блок не рендерится вообще, следа не остаётся |
| Есть прогоны | expander со счётчиком, таблица, выбор, кнопка ОТКРЫТЬ |
| `status.json` битый | строка со статусом `INVALID`, из выбора исключается |
| `findings.json` не читается | `st.error` «Результаты запуска повреждены или не завершены» |

## Системные сообщения

Четыре типа (`info`, `success`, `warning`, `error`) на кадре
[34](../01-screens/34-component-alerts.png) выглядят одинаково: один и тот же
серый прямоугольник, один цвет текста, иконка обесцвечена принудительно.
Правило — строки 843–846 в `app.py`. Отличить предупреждение от успеха можно
только прочитав текст.

## Адаптив

Брейкпоинтов в CSS нет ни одного. Сайдбар жёстко зафиксирован:
`min-width:360px; max-width:360px`. Основная область — `max-width:1180px`.
На 1024 px ([28](../01-screens/28-narrow-1024.png)) таблицы теряют правые
колонки, заголовок переносится, `st.code` в шагах трейса режет текст.
Медиазапрос в CSS ровно один и он про `prefers-reduced-motion`.
