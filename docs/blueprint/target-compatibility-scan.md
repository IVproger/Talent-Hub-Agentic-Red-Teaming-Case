# Скан совместимости: гибки ли мы для произвольных стендов

Проверка абстракции границы (adapter / identities / evidence) против пяти
стендов из [`../../artifacts/similar-stands-research.md`](../../artifacts/similar-stands-research.md).
Вопрос: сколько кода нужно, чтобы подключить каждый, и каких источников
evidence не хватает.

## Что уже есть в Ядре

- **Адаптеры:** `http-chat` (единственный). Личности: `static`, `docker-exec-mint`.
- **Evidence-провайдеры:** `db-query` (mongo/postgres/sqlite/qdrant по driver),
  `log-regex` (docker-log | file | http | cli-json), `http-canary`, `json-file`,
  `jsonl-file`, `state-reset`.
- **EvidenceKind:** MEMORY_SNAPSHOT · TOOL_CALLS · EXTERNAL_CALLBACK · AUDIT_LOG · SESSION_RESET.

## Стенды

Тир подключения: **профиль** (0 кода) · **+провайдер** (~50–100 строк) · **+адаптер** (~150 строк) · **вне области**.

| Стенд | Транспорт → адаптер | Источники evidence | Покрыто нашим | Тир |
|---|---|---|---|---|
| **genai-invest-stand** (наш) | HTTP chat → `http-chat` ✓ | Mongo, access-log, redis-reset | `db-query`+`log-regex`+`state-reset` ✓ | профиль |
| **DVAA** | HTTP chat ✓ / MCP / A2A | `dvaa logs --json`, canary, `audit.jsonl`, memory-файлы | `log-regex(cli-json)`·`http-canary`·`jsonl-file`·`json-file` ✓ | **профиль** (chat); +адаптер (MCP/A2A) |
| **DVMCP** | MCP JSON-RPC → нет | MCP-ответы, `state.json` | `json-file` ✓, транспорт — нет | +адаптер (MCP) |
| **AgentDojo** | in-process pip → нет | диф объекта-окружения, utility-функция | нет провайдера | +адаптер + провайдер |
| **ASB** | in-process harness → нет | захваченные вызовы функций, ASR/utility | нет провайдера | +адаптер + провайдер |
| **WASP** | web-агент → нет | состояние sandbox-приложения (GitLab/Reddit) | `db-query` если есть доступ к БД | +адаптер (web) |

**Вывод по гибкости:** для HTTP / white-box целей — да. **DVAA подключается почти
одним профилем** (его chat-боты), что и есть доказательство переносимости. Новый
транспорт (MCP, A2A, in-process, web) — это +1 адаптер за границей, ядро
(нормализация, предикаты, вердикт) не трогается. Это подтверждает выбранную
границу «HTTP + плагинуемый evidence»: in-process-стенды (AgentDojo/ASB) вне
текущей области по решению, но шов (Protocol) их пустит позже без переписи ядра.

## Каких источников не хватает (по приоритету)

1. **OTel / trace-провайдер** — читает tool calls И reasoning-спаны ReAct из
   OpenTelemetry цели. Универсален для **любой** реальной системы с трейсингом
   (банк), не зависит от внутренностей. Разблокирует ASI01 (goal hijack — нужно
   «почему», а не только «что») и снимает самый дорогой пункт контракта
   подключения. **Высший приоритет; кандидат в Ядро.**
2. **Canary на нашем стенде** — провайдер `http-canary` есть, но у стенда нет
   приёмника. Нужен для доказательства эксфильтрации и **распространения**
   компрометации (ASI02 chaining; прямое требование кейса).
3. **In-process / object-introspection провайдер** — диф объекта-окружения и
   захват вызовов функций. Только если заносим AgentDojo/ASB. Сейчас вне области.
4. **Vector-driver для `db-query`** (qdrant/pgvector) — объявлен, не реализован.
   Нужен для ASI06 / LLM09 (память в вектор-сторе).

## Для чего источника нет вообще

- **Наблюдение за планировщиком** (ASI01 goal hijack, «выбрал инструмент по
  ложной причине») — tool calls показывают исход, не план. Единственный источник —
  OTel-спаны ReAct-цикла. Пока нет → такие сценарии `UNOBSERVABLE`/`indirect`.
- **Межагентный канал** (ASI07/08) — нужен доступ к A2A/шине. У одиночного
  агента `NOT_APPLICABLE`; у DVAA есть A2A.

## Что заложить в Ядро, чтобы «любая система» была настоящей

- **Реестр плагинов.** Adapter / Identity / Evidence регистрируются по имени
  (entry-point/registry), новый провайдер или адаптер **не редактирует** ядро.
  Это и есть гарантия гибкости (сейчас в спеке §2 они перечислены как модули, но
  реестр не заявлен явно).
- **OTel-провайдер** в списке провайдеров Ядра (§4.1) — единственное добавление,
  делающее «любая система» реальной, а не декларативной.
- **Расширяемый EvidenceKind** + capability-гейт корректно обрабатывает
  неизвестный вид (уже спроектировано).
- Зарезервировать (не строить сейчас): MCP-адаптер, in-process-адаптер — шов готов.
