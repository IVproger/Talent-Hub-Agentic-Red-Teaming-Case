# Похожие стенды-мишени для agentic AI security

> Отфильтрованный и отранжированный результат Deep Research по поиску аналогов
> нашего стенда (**намеренно уязвимой системы-мишени**, которую атакуют, а не
> инструмента-атакующего). Из исходной выдачи удалены варианты, которые
> существенно менее функциональны, чем наш стенд, либо являются методами атаки,
> а не мишенью (см. раздел «Отфильтровано»).

**Главный вывод:** прямого аналога, закрывающего все 9 критериев нашего стенда
одновременно (ReAct-агент + реальный MCP tool-calling + двухуровневая память +
BAC через аргументы инструментов + memory poisoning с межпользовательским
распространением + переключаемые vulnerable/protected режимы + Keycloak/OAuth2
IAM + полистек хранилищ + Langfuse/OTel + детерминированные цели), не существует.
Ландшафт делится на (1) намеренно уязвимые агентные приложения / MCP-стенды для
CTF-обучения и (2) академические benchmark-окружения с детерминированными
целями. Наш стенд — единственный, кто объединяет оба кластера.

## Критерии сопоставления (наш стенд = эталон)

1. Reasoning-агент (ReAct/планировщик), а не чат-бот
2. Реальный MCP / tool-calling
3. Многоуровневая память (рабочая + долговременная персистентная)
4. Классы атак: BAC через аргументы инструментов / memory poisoning / indirect injection / влияние на планирование
5. Переключаемые vulnerable / protected режимы
6. Docker + IAM (OAuth2/OIDC) + мультихранилище
7. Встроенная трассировка Langfuse / OTel
8. Детерминированные, проверяемые по состоянию цели атаки
9. Прикладной бизнес-домен поверх синтетических данных

Оценка покрытия: ● совпадает (1.0), ◐ частично (0.5), ○ нет (0.0).

### 1. Damn Vulnerable AI Agent (DVAA) — ближайший аналог
[github.com/opena2a-org/damn-vulnerable-ai-agent](https://github.com/opena2a-org/damn-vulnerable-ai-agent) · активен (v0.9.x, июль 2026)

Позиционируется как «DVWA для AI-агентов»: флот агентов с MCP-инструментами
(ToolBot/DataBot/PluginBot/ProxyBot, порты 7010–7013), разворачивается через
`docker compose up`. **Ключевое совпадение** — переключаемые vulnerable/protected
пары (RAGBot vs RAGBot-AIM, `AIM_ENFORCEMENT` on/off) с детерминированным
A/B-верификатором: внешний canary-listener фиксирует факт эксфильтрации, а не
текст ответа. MemoryBot — memory injection с cross-session persistence.
**Чем уступает нам:** не единый ReAct-планировщик, а набор из 19 ботов; нет
формальной «рабочая + долговременная БД» памяти и явного межпользовательского
распространения отравления; BAC через аргументы инструментов не выделен как
отдельный класс (упор на capability abuse / MCP path traversal / SSRF); нет
Keycloak/OAuth2, Langfuse/OTel, мультихранилища и прикладного домена.

### 2. Agent Security Bench (ASB) — самое широкое покрытие атак
[github.com/agiresearch/ASB](https://github.com/agiresearch/asb) · активен

10 сценариев (включая финансовые/инвестиционные), 10 типов агентов, 400+
инструментов, 27 методов атак/защит. **Совпадает по критерию 4:** явные
memory poisoning attack и Plan-of-Thought backdoor среди векторов; финансовый
домен близок к «банковскому ассистенту»; детерминированные метрики ASR/utility.
**Чем уступает нам:** инструменты — симулированные python-функции, не реальный
MCP; нет docker-стенда с IAM/мультихранилищем; vulnerable/protected — программные
флаги defense-методов, а не режим уровня инфраструктуры; BAC через аргументы
инструментов отдельно не выделен.

### 3. AgentDojo — самое зрелое академическое окружение
[github.com/ethz-spylab/agentdojo](https://github.com/ethz-spylab/agentdojo) · активно поддерживается (используется US/UK AISI)

Агент вызывает инструменты по задачам в 5 доменах (в т.ч. banking).
**Совпадает по критерию 8:** формальные utility-функции по состоянию среды, не
LLM-судья; есть сравнение defense/no-defense (`--defense`). **Чем уступает нам:**
собственный tool-calling API, не MCP; нет памяти между запусками; pip-пакет, а не
docker/IAM-стек; из атак — только indirect prompt injection (нет BAC/memory
poisoning).

### 4. Damn Vulnerable MCP Server (DVMCP) — ближайший «MCP-стенд»
[github.com/harishsg993010/damn-vulnerable-MCP-server](https://github.com/harishsg993010/damn-vulnerable-MCP-server) · активен

10 нарастающих по сложности challenge-серверов (prompt injection, tool poisoning,
excessive permissions, rug pulls, tool shadowing, indirect injection, token theft,
RCE, remote access control, multi-vector chains), реальный MCP JSON-RPC, локальный
Docker. **Чем уступает нам:** нет единого reasoning-агента (изолированные
серверы); персистентная память — простые `state.json`, а не 2-уровневая
архитектура; нет vulnerable/protected режимов, IAM, Langfuse/OTel, бизнес-домена.

### 5. WASP (Meta FAIR) — развёртываемая sandbox-мишень (веб-модальность)
[github.com/facebookresearch/wasp](https://github.com/facebookresearch/wasp) · активен (NeurIPS'25)

Веб-навигационный агент атакуется через planted-инструкции в self-hosted клонах
GitLab и Reddit (sandboxed VisualWebArena). **Совпадает по критериям 6 и 8:**
воспроизводимая развёртываемая мишень + детерминированные ASR-intermediate /
ASR-end-to-end по состоянию среды. **Чем уступает нам:** веб-агент, а не MCP
tool-calling; нет памяти; только indirect prompt injection; другой домен
(GitLab/Reddit, не финансы).

## Отфильтровано (существенно менее функционально или не «стенд»)

| Проект | Причина исключения |
|--------|--------------------|
| **MINJA / AgentPoison / MemPoison** ([2503.03704](https://arxiv.org/html/2503.03704v5), [AgentPoison](https://github.com/AI-secure/AgentPoison)) | Это *методы атаки* (red-team техники отравления памяти), а не система-мишень. Требовалась мишень, а не атакующий подход. |
| **ToolEmu** ([github](https://github.com/ryoungj/toolemu)) | Инструменты эмулируются другой LLM, вердикт — LLM-судья (не детерминированно), не разворачивается как стенд. |
| **InjecAgent** ([ACL'24](https://aclanthology.org/2024.findings-acl.624.pdf)) | Узкий одновекторный бенчмарк (только indirect injection), симулированные тулы, не обновляется, не разворачивается. |
| **MCPSecBench** ([2508.13220](https://arxiv.org/pdf/2508.13220.pdf)) | Протокольный тест-сьют MCP без агента, памяти, домена, режимов и IAM — существенно у́же нашего стенда. Полезен только если фокус чисто на протоколе MCP. |

## Пробелы = потенциальная новизна нашего стенда

Ни один аналог не сочетает одновременно:

- **BAC через аргументы инструментов**, где авторизацию решает LLM вместо
  внешнего IAM — как отдельный формализованный, измеряемый класс (у DVAA/DVMCP
  лишь косвенно, внутри «capability abuse» / «excessive permissions»).
- **Двухуровневую память** (сессионный KV + персистентная документная БД) с
  демонстрацией **межпользовательского распространения** отравления в
  развёртываемом приложении (MINJA/AgentPoison показывают это лишь в harness'е).
- **IAM уровня Keycloak/OAuth2-OIDC** внутри агентного MCP-стенда (ни у кого нет).
- **Встроенную трассировку Langfuse/OTel** как часть самого стенда.
- **Vulnerable/protected режимы на уровне всей инфраструктуры**, а не одного
  флага/пары ботов.
- **Детерминированную проверку по снимкам памяти + access-логам БД** в связке с
  реалистичным прикладным доменом.
