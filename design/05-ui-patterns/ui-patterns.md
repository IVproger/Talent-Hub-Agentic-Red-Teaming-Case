# UI-паттерны Альфы: что снято с живых интерфейсов

Документ фиксирует не заявленные, а **фактически применяемые** приёмы.
Все значения получены замером computed-стилей на загруженных страницах
скриптом `design/capture_sites.py`, сырые данные лежат в `04-references/extracted/`.

## Ключевое открытие: тёмная тема у бренда своя

Раздел `alfabank.ru/corporate` свёрстан целиком в тёмной теме. Это снимает
главный риск нашего проекта: инструмент безопасности в тёмном интерфейсе
не будет выглядеть чужим для банка.

Замеренные значения корпоративного раздела ложатся на токены один в один:

| Замер на странице | Токен дизайн-системы |
| --- | --- |
| `rgb(18, 18, 19)` фон страницы | `--color-dark-base-bg-primary` `#121213` |
| `rgba(215, 215, 229, 0.07)` фон карточек | `--color-dark-neutral-translucent-100` `rgba(214, 214, 229, 0.07)` |
| `rgba(222, 222, 240, 0.12)` фон карточек 2-го уровня | `--color-dark-neutral-translucent-300` |
| `rgba(255, 255, 255, 0.94)` основной текст | `--color-dark-text-primary` |
| `rgba(238, 238, 251, 0.55)` вторичный текст | `--color-dark-text-secondary` |
| `rgb(239, 49, 36)` кнопка | `--color-static-brand-red` |

## Поверхности на тёмном строятся прозрачностью, а не цветом

Это самый переносимый приём из всех найденных. Карточка на тёмном фоне
не заливается сплошным `#1c1c1e`, а получает полупрозрачную белёсую вуаль.

```css
/* так делает Альфа */
background: rgba(214, 214, 229, 0.07);   /* --color-dark-neutral-translucent-100 */

/* а не так */
background: #1c1c1e;
```

Зачем это нужно нам: в дашборде безопасности карточки лежат на разноцветных
подложках, включая приглушённые заливки статусов. Прозрачная поверхность
сохраняет единую логику вложенности на любом фоне, сплошная — нет.

Шкала вложенности на тёмном:

| Уровень | Токен | Значение |
| --- | --- | --- |
| Фон страницы | `--color-dark-base-bg-primary` | `#121213` |
| Карточка | `--color-dark-neutral-translucent-100` | `rgba(214, 214, 229, 0.07)` |
| Вложенный блок | `--color-dark-neutral-translucent-300` | `rgba(222, 222, 238, 0.13)` |
| Наведение | `--color-dark-neutral-translucent-400` | `rgba(231, 231, 248, 0.18)` |
| Модальное окно | `--color-dark-modal-bg-primary` | `#1c1c1e` |

## Радиусы: 32 пикселя как норма

Частотность радиусов по всем снятым страницам:

| Радиус | Частота | Где |
| --- | --- | --- |
| `32px` | доминирует, 66–81 вхождений на страницу | карточки, секции, контейнеры |
| `24px` | часто | карточки второго уровня, кнопки в героях |
| `99px` | часто | кнопки-таблетки, сегментированные переключатели, теги |
| `16px` / `10px` / `8px` | регулярно | поля ввода, мелкие плашки, иконочные контейнеры |
| `50%` | точечно | аватары, круглые иконки |

Встречаются и асимметричные радиусы для секций, наезжающих друг на друга:
`64px 64px 0 0` и `4px 4px 0 0`.

**Оговорка для нашего продукта.** 32 пикселя — радиус витрины. В плотной
таблице находок он неуместен: строка высотой 44 пикселя со скруглением 32
превращается в капсулу. Рабочее предложение: оставить 32 для крупных
контейнеров-панелей, а внутри перейти на 12–16, сохранив 99 для кнопок и тегов.
Это удержит пластику бренда, не ломая плотность.

## Тени почти не используются

На главной и продуктовых страницах теней в замерах нет вовсе. На корпоративной
нашлись две штуки на всю страницу. Разделение слоёв делается цветом
поверхности и радиусом, а не тенью.

Дизайн-система при этом содержит развитую систему теней: 20 токенов,
четыре семейства (обычные, `-hard`, `-up`, `-hard-up`), каждая тень
многослойная из 2–6 наложений с прозрачностью 0.02–0.2. Они предназначены
для всплывающих слоёв, а не для карточек в потоке.

Вывод для кита: **карточки без тени, тень только у оверлеев** —
выпадающих списков, тултипов, модальных окон.

## Кнопки

| Тип | Как выглядит |
| --- | --- |
| Главное действие | заливка `#ef3124`, белый текст, скругление 12–24px или pill |
| Вторичное на тёмном | полупрозрачная белёсая заливка, белый текст |
| Вторичное на светлом | заливка `#f2f3f5`, тёмный текст |
| Третичное | без заливки, только текст |

На экране главной страницы фирменно-красная кнопка ровно одна. Это
подтверждает правило экономии акцента.

## Сегментированный переключатель

Повторяющийся компонент: горизонтальная группа опций в капсуле, активная
опция получает контрастную заливку-пилюлю. На светлом фоне активная пилюля
тёмная, на тёмном — светлая. Хороший кандидат на переключатель режимов
в нашем инструменте: тип атаки, срез отчёта, тема.

## Типографика в бою

| Стиль | Роль |
| --- | --- |
| 16px / 400 | основной текст, самый частый стиль на всех страницах |
| 14px / 400 / 20px | вторичный текст, подписи |
| 14px / 500 / 20px | ссылки, мелкие действия |
| 22px / 700 / 26px | заголовки блоков |
| 30px / 700 / 36px | заголовки разделов |
| 40px / 700 / 48px | заголовок страницы |

Веб-шрифтов нет: замеры показывают только системный стек
`-apple-system, system-ui, Segoe UI, Roboto, …`.

## Цветовые блоки

Разнообразие на витрине даёт не бренд-красный, а насыщенные заливки
вспомогательных цветов: лавандовый, циан, синий, мятный, салатовый
`rgb(234, 255, 179)`, персиковый `rgb(255, 229, 199)`, голубой `rgb(214, 230, 255)`.
Карьерный портал использует фирменный фиолетовый `#6a4dff`.

Все эти оттенки живут в группах `decorative` и `promo` дизайн-системы
(306 и 111 токенов на тему соответственно).

## Чего в брендовых интерфейсах нет и что нам придётся спроектировать самим

Публичные сайты Альфы — это витрина. В них отсутствуют компоненты,
без которых наш инструмент не работает:

* плотная таблица находок с сортировкой и фильтрами;
* визуализация графа: цепочка «вход → контекст → память → инструмент → действие»;
* просмотрщик трассировки со свёрнутыми шагами агента;
* diff состояния памяти агента до и после атаки;
* матрица покрытия по MITRE ATLAS;
* индикатор Attack Success Rate во времени.

Для них берём токены Альфы как палитру и типографику, а структуру
заимствуем из жанра панелей наблюдаемости. Готовые компоненты
из Core Components (`github.com/core-ds/core-components`) закрывают
базовый слой: таблицы, поля, модальные окна, бейджи, вкладки.
