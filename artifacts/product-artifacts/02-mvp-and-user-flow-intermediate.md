# MVP и пользовательский сценарий

## Основной сценарий

1. Специалист добавляет описание агента, архитектуру и конфигурацию целевого стенда.
2. Запускает `doctor` и проверяет доступность стенда и моделей.
3. Выбирает тип атаки, роли пользователей и число прогонов.
4. Инструмент выполняет сценарий и собирает память, tool calls и журналы.
5. Детерминированные assertions проверяют, достигнута ли цель.
6. Пользователь получает ASR, evidence и отчёт. Сценарий можно повторить после исправления.

Для демонстрации тот же процесс доступен в локальном Streamlit-интерфейсе.

## Что входит в промежуточный MVP

| Входит | Пока не входит |
|---|---|
| Один учебный инвестиционный агент | Автоматическое подключение любого агента |
| Adaptive BAC и четыре YAML-сценария | Полная генерация всех классов атак |
| Несколько пользователей, сессий и шагов | Массовые параллельные кампании |
| Снимки MongoDB и журнал tool calls | Универсальный state adapter |
| Детерминированный ASR | Автоматическая оценка бизнес-ущерба |
| CLI, локальный Streamlit, Markdown/JSON | Корпоративная ролевая модель и серверный UI |
| Опциональная Langfuse-трассировка | Проверенный production deployment Langfuse |

## Как продуктовые решения повлияли на код

| Продуктовое решение | Техническая реализация |
|---|---|
| Проверяем агентную систему, а не отдельную модель | Сбор состояния памяти и аргументов инструментов |
| Evidence важнее красивого ответа | Детерминированные assertions; ответ LLM не решает verdict |
| Сначала нужен интегрируемый инструмент | Единый CLI и машиночитаемые JSON-артефакты |
| Проверки должны повторяться | YAML-сценарии, run ID и отдельный каталог каждого запуска |
| Банк не может зависеть от внешнего SaaS | Docker Compose, локальный UI и поддержка Ollama |
| Для демо нужен понятный путь | Streamlit использует тот же pipeline, что и CLI |

## Критерий завершения MVP

MVP считается доказанным, когда один и тот же сценарий:

- воспроизводится несколько раз;
- оставляет проверяемый след в памяти или tool call;
- даёт одинаково рассчитанный verdict в CLI, UI и артефактах;
- повторяется после включения защиты и показывает изменение ASR.
