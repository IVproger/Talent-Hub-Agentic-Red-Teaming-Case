# Сквозное — рамки проверки, разнообразие, судьба находки (спек)

> Сквозной спек трёх аспектов, не привязанных к одному эпику:
> **рамки авторизованного тестирования** (US-34/35), **метрика
> разнообразия/покрытия** (US-13), **судьба находки** (US-36). Каждый
> плагинится в уже описанные части.
>
> Дата: 2026-09-05 · Команда: Zero Trace · Продукт: MOROK

## Зачем отдельно

Эти три вещи проходят через весь флоу и не помещаются в один эпик: рамки —
условие продажи в регулируемый сегмент; разнообразие — метрика, которую
кейсодатель ценит **выше** числа успехов; судьба находки — то, что превращает
отчёт в процесс, а не в документ.

---

## 1. Рамки авторизованного тестирования (US-34, US-35)

Автономный генератор атак против систем банка обязан иметь формальную рамку
допустимого и работать внутри контура. Дёшево в реализации, критично для
доверия.

### 1.1 Гейт разрешения (US-34)
Перед кампанией — явное подтверждение авторизации:

- в профиле/кампании — обязательное поле `authorization` (кто разрешил, окно, scope);
- без него `run` **не стартует** (наравне с preflight), даже на своём стенде отметка «учебный полигон, синтетические данные»;
- зафиксировано в `campaign.json` и в условиях воспроизведения отчёта (E7 §8).

### 1.2 Работа в контуре (US-35)
- MOROK on-prem: ни контекст, ни трейсы, ни находки не уходят во внешний SaaS (требование регулируемого сегмента, интервью);
- LLM-роли (генератор/репортёр) — конфигурируемый провайдер, допускающий локальный/внутренний эндпоинт;
- для внешних целей — режим без записи (открытый вопрос №4 бэклога): `run --read-only` запрещает изменяющие состояние шаги (`verify`, отравление), оставляя только наблюдаемое.

### 1.3 Фокус атак
Явное правило (Тимур [55:02]): фокус не на обход alignment/jailbreak, а на
уязвимости конкретной системы (BAC, память, tools). Отражается в приоритете
шаблонов E3 и в отсеве «просто jailbreak на одного пользователя» как
неинтересного.

## 2. Метрика разнообразия / покрытия (US-13)

Кейсодатель ценит репрезентативность **выше** числа успехов — значит,
успешность и покрытие показываются вместе (защита от накрутки).

### 2.1 Что считаем
- **Покрытие стандарта:** сколько пунктов ASI/LLM проверено из проверяемых (из отчёта о покрытии E3 §4);
- **Разнообразие подходов:** число различных атакующих подходов на сценарий (из дедупа E4 §7 — сколько «новых», не повторов);
- **Разнообразие поверхности:** сколько инструментов/хранилищ/границ затронуто.

### 2.2 Где показываем
Наравне с ASR — в техническом отчёте (E7 §5.3) и в предпросмотре. Формула
покрытия и разнообразия входит в отчёт (как и ASR, US-24 AC4). Детерминированно.

### 2.3 Почему
ASR в адаптивной кампании легко «накрутить»; покрытие+разнообразие отвечают
на реальный вопрос кейсодателя «покрыли ли ключевой функционал», а не «сколько
раз пробили».

## 3. Судьба находки (US-36)

Как только у находки появляется статус, MOROK перестаёт быть генератором
отчётов и становится частью процесса.

### 3.1 Жизненный цикл
Статус находки (в базе знаний E6):

```
открыта → подтверждена → передана команде агента → исправлена → перепроверена (E8) → закрыта | переоткрыта
```

### 3.2 Хранение и переходы
- статус — поле записи находки в `knowledge.db` (E6);
- переход `исправлена → перепроверена` завязан на E8 (`regress run`): результат повтора двигает статус;
- история статусов сохраняется (аудит).

### 3.3 Экспорт (открытый вопрос №5)
Статусы ведутся внутри MOROK или экспортируются во внешнюю систему (их
AppSec-платформа, куда findings «трекаются и анализируются» — Тимур).
По умолчанию — внутри; экспорт `findings.json` уже машиночитаем для
интеграции. Решение — за продуктовым владельцем.

## 4. Модули и интерфейсы

```
campaign/authorization.py   # гейт US-34: проверка authorization до старта
reporting/metrics.py        # покрытие + разнообразие (US-13)
knowledge/lifecycle.py      # статусы находок + переходы (US-36)
```


## 5. Трассируемость (сквозное → US)

| Механизм | US |
|---|---|
| Гейт разрешения, работа в контуре, read-only режим, фокус атак | US-34, US-35 |
| Покрытие + разнообразие наравне с ASR | US-13 |
| Жизненный цикл находки, переходы, экспорт | US-36 |
