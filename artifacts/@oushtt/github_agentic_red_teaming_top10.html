01 / ВЫВОД

Рынок закрывает части, не весь цикл

Популярные сканеры хорошо генерируют и оценивают атаки. Agent-бенчмарки умеют проверять фактические tool calls. Memory-проекты видят сохранённое состояние. Но связка «межсессионная атака → изменение памяти → триггер → вредоносный tool call → state diff → ASR» почти нигде не является готовой сквозной абстракцией.

Claude Code + сильная модель — уже отличный исследователь атак. Но без независимого исполнителя и oracle он одновременно придумывает эксперимент, проводит его, ведёт заметки и выносит вердикт. Это быстро, но плохо масштабируется в доказательство.

SCANNER
Даёт масштаб, каталог атак, генерацию payload’ов, CI и отчётность.
EVAL RUNTIME
Даёт повторяемый запуск, sandbox, трассу и машинные scorer’ы.
AGENT BENCH
Даёт инструменты, контролируемую среду и ground truth по побочным эффектам.
MEMORY LAYER
Даёт provenance, проверки записи/чтения, snapshots и rollback.

Короткая рекомендация

Для MVP разумнее всего взять PyRIT или Promptfoo как слой кампаний и генерации, заимствовать у Inspect AI модель воспроизводимого запуска и event log, у AgentDojo / ASB — проверку реального состояния среды, а у OWASP Agent Memory Guard — provenance и snapshot/diff памяти. Сильный coding-agent harness оставить внутри системы как адаптивного attack planner, но не как источник истины.

02 / МЕТОДИКА

Как составлен рейтинг

Сначала отобраны проекты, которые реально можно использовать или расширить для AI/agent red teaming. Затем рассчитан сравнительный балл. Он нужен для навигации, а не для объявления абсолютного победителя.

WEIGHT / 45%Близость к кейсу

Многошаговость, tool calls, состояние среды, persistent memory, отложенный триггер, trace и state-level oracle.

WEIGHT / 35%GitHub-сигнал

Логарифмически нормализованное число звёзд: зрелость экосистемы важна, но 25k звёзд не должны в 150 раз перевешивать узкий memory benchmark.

WEIGHT / 20%Актуальность

Дата последнего push на 02.09.2026. Активность — полезный сигнал поддержки, но не гарантия качества конкретной функции.

SCORE = 0.45 × RELEVANCE + 0.35 × LOG(STARS) + 0.20 × RECENCY

Звёзды и даты получены через GitHub API 2 сентября 2026 года. Числа динамические. Relevance — редакционная оценка применимости именно к кейсу Альфа-Банка, а не общая оценка качества проекта.

05 / ПРОФИЛИ

Как работает каждый

Для каждого проекта: механизм, реальное преимущество перед универсальным harness и пробел относительно кейса. Формулировка «лучше» здесь означает более воспроизводимое, измеримое или специализированное решение — не более умную модель.

01

Promptfoo

★ 24,750MITpush 02.09
FIT / 96

Что делает. Developer-first CLI и библиотека для eval/red-team LLM-приложений, RAG и агентов. Из YAML-конфигурации строит матрицу целей, plugins-вредоносных намерений, attack strategies и graders; выполняет тесты, считает pass/fail, хранит результаты и формирует web-отчёт.

PURPOSE → PLUGINS → STRATEGIES → TARGET/SESSION → OTEL TRACE → GRADER → FINDING

Как работает для агентов. Есть stateful multi-turn стратегии Crescendo, GOAT и Hydra, косвенная инъекция через web-контент, композиция стратегий, управление сессиями и OpenTelemetry-трассировка. Траектория включает LLM-вызовы, guardrails, tools, shell-команды, ошибки и может быть передана grader’у или следующей итерации атаки.

Сильнее простого harness

Даёт декларативный corpus, массовые прогоны, бюджетирование, готовые классификации, независимое grading, CI и воспроизводимый отчёт. Trace отличает обещание агента от фактического tool call.

Где harness всё ещё сильнее

Сам по себе Promptfoo не знает семантику вашей БД и долговременной памяти. Межсессионный state reset, заражение другого пользователя и проверку банковского side effect придётся оформить custom provider’ом и детерминированными assertions.

Для MVP: лучший готовый внешний слой кампаний и отчётности; дописать scenario/state adapter и memory diff.
02

PyRIT

★ 4,393MITv1.0.1
FIT / 84

Что делает. Microsoft Python Risk Identification Tool — модульный framework для автоматизации AI red teaming. Основные сущности: objective target, adversarial target, attacks/executors, prompt converters, scorers и memory эксперимента.

OBJECTIVE → EXECUTOR → CONVERTERS → TARGET ↔ ADVERSARIAL MODEL → SCORERS → MEMORY

Как работает. Single-turn executor отправляет один удар; multi-turn адаптируется по ответам цели; compound executor соединяет несколько атак; workflow описывает произвольную многошаговую процедуру; benchmark прогоняет фиксированный набор. Target-адаптеры позволяют подключать не только модель, но и приложение.

Сильнее простого harness

Явно разделяет цель, атакующую модель, преобразования и scorer. Хранит полный эксперимент, масштабирует кампании и позволяет повторять одну цель разными техниками вместо свободного дрейфа агента.

Критическая оговорка

PyRIT memory в первую очередь хранит историю red-team эксперимента. Это не автоматическая инспекция долговременной памяти атакуемого агента. Для кейса нужны target-side memory API, снимки и отдельные state scorers.

Для MVP: наиболее естественная Python-основа для собственного multi-step executor и attack DSL.
03

Giskard v3

★ 5,801Apache-2.0push 02.09
FIT / 81

Что делает. Переписанная v3 — async-first набор модулей для тестирования agentic systems. `giskard-checks` даёт Target → Scenario → Interaction → Check → Suite; `giskard-scan` автоматически генерирует vulnerability suite по текстовому описанию агента.

AGENT DESCRIPTION → GENERATED SUITE → SHARED TRACE → PER-STEP CHECKS → REPORT

Как работает. Multi-turn Scenario последовательно вызывает агента, добавляет каждый шаг в общую trace и ставит проверку сразу после нужного взаимодействия. `FnCheck`, LLM-as-judge и spy позволяют проверять содержание, историю и внутренние вызовы. Target может быть sync/async black box и при желании возвращать trace.

Сильнее простого harness

Превращает гипотезу в исполнимую спецификацию с точкой отказа. Общая trace и check после каждого шага локализуют момент компрометации; suite удобно превращается в regression test.

Где нужен свой слой

Conversation state поддерживается хорошо, но долговременная память между независимыми сессиями и реальный diff хранилища не являются доменной моделью framework. Их надо передавать в trace или проверять через `FnCheck`.

Для MVP: сильная основа для читаемого scenario API и пошаговых assertions.
04

DeepTeam

★ 2,648Apache-2.0push 21.08
FIT / 80

Что делает. Специализированный framework для black-box red teaming LLM-систем. Комбинирует 50+ классов уязвимостей, 20+ single/multi-turn техник, simulator model и LLM-as-judge metrics. В актуальном каталоге есть tool metadata poisoning, cross-context retrieval, goal theft, tool orchestration abuse, autonomous drift и exploit tool agent.

VULNERABILITY → BASE ATTACK → ENHANCEMENT/PROGRESSION → AGENT + TOOLCALLS → BINARY METRIC

Как работает для tool-агента. Callback возвращает не только текст, но и список `ToolCall` с именами, аргументами и output. Attack создаёт one-shot enhancement либо последовательность turns. Специализированная metric даёт бинарный балл и объяснение.

Сильнее простого harness

Богатая современная taxonomy именно agentic-рисков, готовые симуляторы, единообразные метрики и масштабируемая генерация. Быстро показывает широкое покрытие жюри.

Где есть риск иллюзии

Переданный `ToolCall` и LLM-judge всё ещё могут оценивать представление о действии, а не авторитетное состояние внешней системы. Memory/context poisoning часто симулируется в prompt, если вы не подключили реальное хранилище.

Для MVP: лучший донор taxonomy и готовых agentic attack generators; дополнить deterministic oracle.
05

Inspect AI

★ 2,686MITUK AISI
FIT / 78

Что делает. Evaluation framework UK AI Security Institute. Task связывает dataset, solver/agent loop, tools, sandbox и scorer. Каждый run сохраняет подробный eval log и transcript; поддерживаются multi-turn диалоги, model grading, tool approval и более 200 готовых evals.

TASK(DATASET, SOLVER, SCORER) → SANDBOX + TOOLS → TRANSCRIPT/SPANS → EVAL LOG

Как работает для внешних harness’ов. Agent Bridge может запускать собственный coding-agent scaffold, проксировать tools через MCP, ограничивать capabilities и всё равно собирать model calls, tool calls и transcript. Sandbox обеспечивает контролируемое окружение.

Сильнее простого harness

Отделяет испытуемого агента от инфраструктуры оценки. Даёт sandbox, capability policy, структурный log, scorer и повторяемый task — именно то, чего не хватает набору Markdown-заметок.

Где harness нужен

Inspect — не готовый генератор атак на память. Attack planner, memory adapters, межсессионный scheduler и сценарии заражения нужно реализовать как task/solver extension.

Для MVP: лучший эталон runner’а, sandbox и трассировки; тяжелее, чем чистый demo, но архитектурно убедителен.
06

Garak

★ 9,092Apache-2.0v0.16.0
FIT / 73

Что делает. «Nmap для LLM»: подключает target через generator, запускает probes, при необходимости мутирует их через buffs, проверяет ответы detectors и агрегирует результаты harness/evaluator’ом. Поддерживает локальные модели, облачные API и произвольный REST.

PROBE → BUFF/MUTATION → GENERATOR/TARGET → DETECTORS → JSONL + HIT RATE

Как работает. Каждый probe кодирует конкретную гипотезу — injection, encoding, leakage, jailbreak и другие. Рекомендуемые detector’ы маркируют поколения PASS/FAIL, детальный поток пишется в JSONL, а плагины расширяют цели и атаки.

Сильнее простого harness

Огромный повторяемый regression corpus, единый plugin contract, batch-generation и простое подключение REST. Отличен как первый широкий baseline и источник payload’ов.

Почему не ядро кейса

Архитектура исторически ориентирована на «prompt → generation → detector». Garak не знает транзакционное состояние агента, жизненный цикл двух сессий и семантику аргументов инструмента без серьёзного нового harness/plugin слоя.

Для MVP: импортировать probes и detectors; не строить вокруг него всю stateful-архитектуру.
07

AgentDojo

★ 789MITNeurIPS 2024
FIT / 66

Что делает. Динамическая среда ETH Zürich для оценки indirect prompt injection атак и защит на LLM-агентов. Набор suite’ов содержит пользовательские задачи, injection tasks, реальные по форме tools, атаки и защиты; их можно комбинировать с выбранной моделью.

USER TASK + INJECTION TASK → TOOL ENVIRONMENT → AGENT PIPELINE → SECURITY + UTILITY RESULTS

Как работает. Вредоносная инструкция помещается во внешнее наблюдение, которое агент получает через tool. Успех определяется выполнением атакующей задачи в контролируемой среде, а utility — выполнением законной пользовательской задачи. Это не только анализ текста ответа.

Сильнее простого harness

Есть независимый ground truth и контролируемые side effects. Можно честно сравнивать ASR защиты с потерей полезности, перебирая одинаковые tasks, attacks, defenses и модели.

Ограничение

Это benchmark-среда, а не универсальный scanner произвольного production-агента. Persistent memory и сценарии банка потребуют новой suite, tools и cross-session lifecycle.

Для MVP: заимствовать разделение user task / attacker goal и programmatic проверку состояния среды.
08

OWASP Agent Memory Guard

★ 165Apache-2.0v0.3.1
FIT / 65

Что делает. Узкий runtime defense и benchmark для OWASP ASI06 Memory & Context Poisoning. Слой ставится между агентом и memory store, пропускает write/read через detectors и policy, а решение превращает в `allow`, `redact`, `quarantine` или `block`.

SOURCE-CLASS WRITE → DETECTORS → POLICY → MEMORY STORE → SNAPSHOT / SECURITY EVENT

Как работает. Проверяет injection, secret/PII leakage, protected-key tampering, size anomaly и self-reinforcement. Каждой записи можно присвоить provenance (`external_tool`, `user_input`, `agent_authored`, `system`). Structured events, snapshots и rollback дают форензику; есть интеграции с LangChain, OpenAI Agents, AutoGen, mem0 и CrewAI.

Сильнее простого harness

Markdown-память не является security boundary. AMG вводит обязательную точку контроля записи, provenance, policy enforcement и восстановление известного состояния — то, что prompt не может гарантировать.

Почему это не готовый red team

Проект в первую очередь защищает и измеряет detector на фиксированном наборе payload’ов. Он не строит адаптивную кампанию, не управляет несколькими пользователями и не ищет неизвестную цепочку атаки.

Для MVP: обязательный референс схемы memory event, snapshot/diff и oracle; атакующий runner строить отдельно.
09

Agentic Security

★ 1,982Apache-2.0v0.7.5
FIT / 60

Что делает. Локальный vulnerability scanner с UI и CLI для LLM/agent endpoints. Принимает raw HTTP-spec с placeholder’ом, загружает встроенные, Hugging Face или локальные CSV-датасеты, мутирует payload’ы, параллельно отправляет запросы и сравнивает failure rate с порогом.

DATASET REGISTRY → MUTATIONS / MULTI-STEP OPTION → HTTP SPEC → FAILURE RATE → CI THRESHOLD

Как работает. Поддерживает text/image/audio probes, multi-step режим, CI config, budget и интеграции с Garak, InspectAI и adaptive attacks. Удобен как оболочка над источниками атак и произвольным API.

Сильнее простого harness

Очень низкий порог подключения endpoint, воспроизводимый batch-fuzzing, готовый UI, бюджеты и CI threshold. Хорош для быстрого baseline на демо.

Почему рейтинг ниже stars

Основная единица всё ещё HTTP prompt/response и failure rate. Заявленная «agentic» направленность не означает встроенный state oracle, tool trajectory или persistent-memory lifecycle.

Для MVP: источник UX-идей и простого HTTP adapter; недостаточно как доменная модель кейса.
10

Agent Security Bench

★ 295MITICLR 2025
FIT / 57

Что делает. Исследовательский benchmark атак и защит для LLM-агентов в 10 прикладных сценариях, включая инвестиции и юридические консультации. Реализует DPI, observation prompt injection, memory poisoning, mixed attack и Plan-of-Thought backdoor.

SCENARIO + YAML → USER / OBSERVATION / MEMORY / POT ATTACK → AGENT TOOLS → ASR + REFUSAL RATE

Как работает. Memory poisoning внедряет вредоносные планы в извлекаемую память, чтобы агент выбрал указанные атакующим tools. OPI меняет tool observation, PoT backdoor активирует скрытое действие триггером. Конфиги управляют типом атаки, tools, моделями, чтением/записью БД и логами.

Сильнее простого harness

Формализует именно те поверхности, которые нужны кейсу, и даёт воспроизводимые метрики ASR/RR на сетке моделей и защит. Это готовая научная база для threat taxonomy и demo-сценариев.

Почему только #10

Небольшая экосистема, research-oriented code, привязка к AIOS и более редкая активность. Это не production-ready connector framework и не универсальная система трассировки.

Для MVP: самый близкий источник attack semantics; переносить идеи и сценарии, а не обязательно весь runtime.
06 / БАЗОВАЯ ЛИНИЯ

Почему не только Claude Code

Сильная модель с целью, описанием системы и каталогом Markdown-файлов памяти — серьёзный baseline. Его нельзя списывать со счетов. Но в red teaming ценность возникает не только из качества гипотез, а из качества доказательства.

Где универсальный harness превосходен

  • Понимает новую кодовую базу и неизвестный API без заранее написанного plugin.
  • Строит гипотезы, меняет план после неудачи и создаёт вспомогательные скрипты.
  • Ведёт исследовательский журнал в Markdown и переносит выводы между сессиями.
  • Легко работает с документами, браузером, terminal и нестандартными каналами доставки.
  • Идеален для первой ручной разведки и генерации новых сценариев.

Где он перестаёт быть инструментом измерения

  • Свободные заметки не являются типизированным event log и не гарантируют полноту.
  • Модель склонна сама оценивать придуманный ею эксперимент; это не независимый oracle.
  • Нет гарантированного reset/seed/version pinning и изоляции параллельных кампаний.
  • Текст «я вызвал tool» не доказывает, что побочный эффект произошёл.
  • Без runner’а трудно честно считать ASR, confidence interval, utility loss и стоимость.

Правильная формула — hybrid. Harness отвечает за exploration: анализ приложения, построение гипотез, выбор следующего шага и минимизацию атаки. Детерминированная система отвечает за execution: жизненный цикл сессий, разрешения, события, снимки, oracle, ASR и отчёт. Если оставить только первую половину, получится впечатляющий pentest-демо, но не воспроизводимый red-team product.
07 / ПРЕДЛОЖЕНИЕ

Что строить для победы

Дифференциатор — не «мы тоже умеем jailbreak». Дифференциатор — causal evidence: какую запись внедрили, кто её извлёк, какой plan изменился, какой tool вызван, какой state действительно пострадал.

01 / MAPSystem Mapper

Описание агента, memory namespaces, tools, роли, разрешения, trust boundaries.

02 / THINKAttack Planner

Сильная модель строит гипотезы и компилирует их в ScenarioSpec.

03 / RUNDeterministic Runner

Setup → poison → close session → trigger another session → cleanup.

04 / PROVETrace + State Oracle

Event log, memory snapshots, tool args, external DB diff, success predicate.

05 / LEARNCampaign Engine

ASR, utility, cost, minimization, replay bundle и regression suite.

Demo, которое отличит вас от scanner’а

Сессия атакующего сохраняет безобидно выглядящую запись в общем memory namespace. Сессия закрывается. Другой пользователь запускает законную задачу. Агент извлекает poisoned memory, меняет план и аргумент инструмента перевода. UI одновременно показывает: исходную запись, provenance, retrieval event, plan delta, tool call, отказ/успех permission layer, diff внешнего ledger и вычисленный goal predicate. Затем один click воспроизводит тот же сценарий на другой модели или защите и обновляет ASR.
