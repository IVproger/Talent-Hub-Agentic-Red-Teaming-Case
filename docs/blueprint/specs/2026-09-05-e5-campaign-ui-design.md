# E5 — Настройка и запуск кампании / демо-UI (спек)

> Спек эпика **E5**. Большая часть E5 (состав, объём, предпросмотр, ход,
> безопасная остановка) уже реализована в Ядре (CLI + runner). Этот спек
> фиксирует, что именно в Ядре, и что остаётся на демо-UI.
>
> Дата: 2026-09-05 · Команда: Zero Trace · Продукт: MOROK

## Цель

Пользователь (R1) контролирует состав, объём и ход проверки (US-15, US-16,
US-18). Рабочий формат — CLI (просьба кейсодателя); Streamlit — только демо.

## Спек-источник

Ядро: §6 runner, §12 CLI. Бэклог: US-15, US-16, US-18.

## 1. Что уже в Ядре (не требует отдельной реализации)

| US | Где | Как |
|---|---|---|
| US-15 выбор состава/объёма | Ядро §12 CLI | `--scenario … / all`, `--trials N`, `--mode`; ограничение допустимыми параметрами |
| US-16 предпросмотр | Ядро §12 CLI | `--dry-run` печатает план + сгенерированные payload'ы; после подтверждения — ровно показанное |
| US-18 ход и безопасная остановка | Ядро §6 runner | `on_event` (стадия/попытка/результат); Ctrl+C → `interrupted`, собранное сохранено, техошибка вне ASR |

То есть E5 как **функциональность** закрыт Ядром. Отдельного кода almost не нужно.

## 2. Что добавляет E5 — демо-экран Streamlit

Тонкий слой поверх тех же данных (US-07 AC3 — один источник):

- экран выбора: профиль@версия, сценарии (из применимых по coverage), trials, режимы;
- предпросмотр: те же payload'ы, что и `--dry-run`;
- ход: прогресс по `on_event`;
- результат: outcome, evidence trace, отчёт, история из `runs/`.

Streamlit **не имеет своей логики** — только рендер результатов runner'а и
чтение `runs/`. Provider/model — read-only из YAML (не редактируются в UI,
как в текущем `serve`).

## 3. Модули

```
ui/app.py    # Streamlit-демо поверх pipeline/runner (перенос на новый runner)
```

Обновляется в рамках Block 4.4/5 Ядра (перевод `serve` на новый runner);
дополнительные экраны — по мере надобности для демо.
