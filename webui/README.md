# MOROK Web UI

Веб-интерфейс поверх движка `agentic_redteam`: FastAPI (`webui/server.py`) отдаёт
статику дизайн-кита (`webui/static/`) и API, запускает **реальные** прогоны тем же
ядром, что и CLI (`execute_agentic_campaign`). Мастер из 6 шагов: Контекст →
Синхронизация → Сценарии → Прогон → Отчёт → Документ для бизнеса.

## Запуск

```bash
cd <repo>
set -a; . ./keys.local; set +a          # грузим OPENROUTER_API_KEY в окружение
python3 -m uvicorn webui.server:app --host 127.0.0.1 --port 8090
```

Открыть **http://127.0.0.1:8090** · остановить — `Ctrl+C`. В фоне:
`nohup … >/tmp/morok-webui.log 2>&1 &`.

Требуется:
- **`. ./keys.local`** — иначе прогон падает на `OPENROUTER_API_KEY is not set`.
  Путь к `docker` (минтинг кредов) сервер сам добавляет в `PATH`.
- **Стенд-цель поднят** (docker compose стенда, `:8600`).

Правки статики (`static/*.html|js|css`) подхватываются перезагрузкой вкладки;
правки Python (`server.py`, движок) требуют перезапуска uvicorn.

## Как строится профиль (важно)

Для **известного стенда** прогон и список на шаге «Сценарии» идут из
**верифицированного профиля** `profiles/genai-invest-stand/1.0.0.yaml`
(`PROFILE_REF`) — детерминированно, со всеми предикатами (вкл. межпринципальный
вызов инструмента), выверенными `entrypoint`/`identities`/`evidence`. Загруженные
на шаге «Контекст» артефакты **кормят генератор атак** как документы (адаптируют
стартовые запросы под контекст цели), но профиль не собирается LLM «на лету» —
так UI-список и реальный прогон гарантированно совпадают.

Инфраструктурные оверрайды (`identities`/`evidence`/`base_url`) для сборки
профиля из артефактов по **новой** цели остаются в ядре (`profile/ingest.py`,
`build_draft`) и покрыты тестами — для CLI-пути.

## API (кратко)

| Метод/путь | Назначение |
|---|---|
| `GET /api/target` · `POST /api/target/upload` · `POST /api/target/reset` | артефакты цели (процесс-локально) |
| `GET /api/preflight` | живые проверки окружения: chat (health стенда), trace (Langfuse), memory (пинг Mongo), reset (провайдер) |
| `GET /api/scenarios` | список сценариев (из `PROFILE_REF`) |
| `POST /api/run?scenario=<id\|all>` | запуск прогона в фоне; `GET /api/status/{id}` — статус/лог |
| `POST /api/run/{id}/cancel` | кооперативная отмена |
| `GET /api/runs` · `GET /api/runs/{id}/findings` · `GET /api/runs/{id}/report` | история, находки, техотчёт |
| `POST /api/runs/{id}/business` · `GET /api/runs/{id}/business.pdf` | LLM-документ для бизнеса + PDF |

## Прогон

- Режим на шаге «Сценарии»: один сценарий или все (сегментед-контрол).
- Живой лог пишется из `status.json` (фазы, стартовые запросы, шаги ReAct:
  что агент отправил и ответ цели).
- По завершении экран «Прогон» финализируется (статус «завершён», вердикты
  PROVEN/NOT PROVEN по сценариям) и открывается отчёт.
- Метрики однозначны: **ASR — по сценариям** (proven/scored), **шаги** — ходы
  ReAct-агента внутри сценария (не «попытки»).
