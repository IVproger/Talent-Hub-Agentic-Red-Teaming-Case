# E2 — Карта поверхности и подтверждение подключения (спек)

> Спек эпика **E2**. Как MOROK показывает компоненты цели, их статус и
> границы аудита. Плагинится в Ядро: потребляет `profile.surface` и
> результат калибровки (`profile check`), производит `surface.json`.
>
> Дата: 2026-09-05 · Команда: Zero Trace · Продукт: MOROK

## Цель

После подключения показать пользователю (R1) и команде цели (R4) **карту
поверхности** — инструменты, интеграции, роли, уровни памяти, каналы входа —
со статусом каждого компонента, чтобы не пропустить критичную поверхность и
согласовать объём аудита до запуска.

## Спек-источник

Ядро: §1.1 (`surface`), §4.3 (calibrate). Бэклог: US-05, US-06, US-07, US-03. `surface.json` = per-agent threat model (Core §1.1).

## Global Constraints (в дополнение к Ядру)

- **Один источник — два вида.** `surface.json` (машиночитаемо) и UI-сводка используют одни и те же данные (US-07 AC3).
- **`check` ничего не меняет** в цели (US-06 AC1). Статусы — из read-only калибровки.
- **Заявлено ≠ подтверждено.** Компонент из профиля, недоступный по факту, помечается явно, не исчезает молча (US-03 AC2, US-06 AC4).

---

## 1. Что показываем (US-05)

Из `profile.surface` + калибровки:

- **инструменты** и их параметры; помеченные `sensitive: true` (работают с данными клиента / ключом доступа) — **приоритет проверки доступа** (US-05 AC2);
- **внешние интеграции** (memory-стора, invest-server, MCP);
- **хранилища памяти** и их `scope` (cross_user/per_user/session);
- **роли** пользователей и точки входа;
- **каналы входных данных** (чат, документ, tool-result — из шаблонов доставки).

## 2. Статус компонента

Каждый компонент получает один из трёх статусов (US-07 AC1):

| Статус | Когда | Источник |
|---|---|---|
| `подключён` | калибровка провайдера/адаптера прошла | `profile check` |
| `недоступен` | заявлен в профиле, но не отвечает/не читается | калибровка FAIL |
| `заявлен, но не подтверждён` | есть в описании, но фактически не наблюдаем | профиль vs факт |

Расхождение описания и факта показывается явно (US-06 AC4) — это и есть US-03 (владелец агента видит, что реально будет проверяться).

## 3. `surface.json` (артефакт = threat model)

```json
{
  "profile": "genai-invest-stand@1.0.0",
  "tools": [
    {"name": "get_portfolio", "args": ["cus","period"], "sensitive": true,
     "principal_from": "cus", "status": "подключён"}
  ],
  "memory": [
    {"id": "policy", "scope": "cross_user", "status": "подключён"}
  ],
  "roles": ["attacker","victim"],
  "entrypoints": ["/v1/chat/completions"],
  "evidence": [{"id":"tool_calls","kind":"tool_calls","status":"подключён"}],
  "coverage": {"standard":"owasp-agentic-2026","provable":7,"total":10}
}
```

Это **per-agent threat model** (методология `Threat Model → OWASP → ATLAS`
из интервью): с него команда начинает аудит, его используют как scope
кампании (US-05 AC3, US-03 AC3).

## 4. Наглядная сводка (US-07)

- CLI: `profile show` печатает карту; `profile coverage` — что доказуемо.
- Демо-экран Streamlit: та же `surface.json` как схема компонентов и точек входа (US-07 AC2). Рабочий формат — текст (просьба кейсодателя), экран — только демо.
- Показывает связи компонент↔точка входа.
