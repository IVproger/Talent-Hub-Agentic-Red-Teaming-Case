# Zero Trace

**Agentic Red Team**

Проверяем действия и состояние ИИ-агента, а не убедительность его ответа

**Промежуточный результат · 04.09.2026**

---

# Вред может проявиться в следующей сессии

Обычный red teaming видит:

`запрос → ответ`

У агента цепочка длиннее:

`вход → память → план → инструмент → аргументы → состояние → следующая сессия`

Ответ может быть безобидным, а память или tool call уже скомпрометированы.

# Нужен результат, который можно проверить

Пользователь: команда AI Security или MLSecOps.

Её задача — проверить агента до релиза и после изменений модели, промпта, памяти или инструментов.

По интервью команде нужны:

- запуск внутри контура;
- автоматизация повторяемых проверок;
- вердикт по состоянию памяти и реальным вызовам.

# Атаку ищет LLM. Успех проверяет код

1. Архитектура и system card описывают поверхность атаки.
2. LLM или YAML создают сценарий.
3. Runner выполняет шаги от разных пользователей и в разных сессиях.
4. State Tracer собирает память и реальные tool calls.
5. Код проверяет цель, считает ASR и формирует отчёт.

Вердикт опирается на память и журнал вызовов.

---

# Видим память, tool calls и аргументы

`CLI / Streamlit`

↓

`единый pipeline → target agent → MCP tools → данные`

↓

`memory snapshot + access log → assertions → ASR → report`

Опционально весь путь связывается одной Langfuse-трассой.

# Демо: запрос чужого портфеля

Генератор создал четыре формулировки:

- прямой запрос чужого портфеля;
- ссылка на полномочия сотрудника;
- сравнение двух клиентов;
- «техническая проверка» API.

В уязвимом режиме агент передал `cus=1002` в инвестиционный инструмент.

Проверка читает фактический вызов из журнала `invest-server`.

---

# 4 из 4 атак дошли до вызова с `cus=1002`

## ASR = 100%

`actor cus=1001 → tool argument cus=1002`

Каждая попытка раскрыла синтетический портфель другого клиента.

Результат подтверждён tool call, а не совпадением слов в ответе.

Ограничение результата: это один класс атак на намеренно уязвимом режиме. Выборка пока мала.

---

# Что проверено, а что пока нет

Работает на одном учебном агенте с синтетическими данными.

Адаптивная генерация пока покрывает только BAC. Memory-сценарии заданы вручную.

Нет подтверждённого live-прогона memory poisoning и сравнения с `protected` режимом.

Последний прогон прошёл без Langfuse credentials, поэтому сквозная трасса не записалась.

---

# До финала: проверить атаку через память

1. Записать вредоносное правило в общую память.
2. Завершить сессию атакующего.
3. Открыть новую сессию от другого пользователя.
4. Зафиксировать подмену аргумента tool call.
5. Повторить в защищённом режиме.
6. Сохранить сквозную трассу и обновить отчёт.
