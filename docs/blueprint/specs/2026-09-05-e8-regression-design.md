# E8 — Воспроизводимость и мониторинг деградации (спек)

> Спек эпика **E8**. Как подтверждённая находка становится воспроизводимым
> тестом и как сравнить результат до/после исправления. Плагинится в Ядро:
> `run --from`, `profile.diff`, сравнение прогонов.
>
> Дата: 2026-09-05 · Команда: Zero Trace · Продукт: MOROK

## Цель

Чтобы подтверждённую уязвимость можно было повторить после исправления и
увидеть, закрыта ли она и не сломалась ли штатная работа агента (US-28,
US-29).

## Спек-источник

Ядро: `runs/` (иммутабельность), `campaign.json`, `run --from`; профиль `diff`. E7: findings/условия воспроизведения. Бэклог: US-28, US-29.

## Global Constraints (в дополнение к Ядру)

- **Исходные артефакты неизменны.** Перепроверка создаёт новый `runs/<id>/`, не трогая прежние (US-29 AC4).
- **Тест = находка.** Воспроизводимый тест несёт те же шаги, роли, параметры и критерий успеха, что и подтверждённая атака (US-28 AC1).
- **Не только «дыра закрыта», но и «продукт не сломан».** Отдельно проверяется штатный сценарий (US-29 AC3).

---

## 1. Находка → воспроизводимый тест (US-28)

Из подтверждённой находки (E7) + условий воспроизведения собирается тест:

- те же профиль@версия, сценарий, payload, роли, режим, `reset_policy`;
- тот же критерий успеха (goal-ассершены);
- запускается на том же target повторно, даёт сопоставимый результат (US-28 AC2);
- результат повтора сохраняется **отдельно** и связан с исходной находкой (US-28 AC3).

`morok regress export --finding <id>` → регрессионный сценарий (обычный
`Scenario`, идёт через тот же runner). Набор находок → **регрессионный
набор** (US-28 AC3).

## 2. Штатный сценарий (`expect: pass`)

Наряду с атакующими сценариями (`expect: attack_success`) каталог несёт
**smoke-сценарий** `expect: pass` — агент должен отработать нормально
(собственный портфель по своему `cus`). Это защита от «доказали безопасность
неработающего агента» (US-29 AC3): если после фикса smoke падает — продукт
сломан, и это видно.

## 3. Сравнение до/после (`reporting/regression.py`)

Одна операция «сравнить два набора результатов по сценариям и по ASR»:

```python
def compare(before: RunResult, after: RunResult) -> RegressionDiff: ...
```

- по каждой атаке: `перестала проходить` / `осталась` / `появилась` (US-29 AC2);
- по итоговому ASR: изменение;
- отдельно — статус smoke-сценария (US-29 AC3).

**Та же операция обслуживает и A/B по режимам** (vulnerable vs protected,
Ядро §6) — отличается только осью сравнения (режим vs версия). Пишется один
раз.

## 4. Мониторинг деградации

Регрессионный набор гоняется при изменении агента (новая версия профиля):
`profile.diff` показывает, что поменялось (инструменты/роли/точки входа/память,
US-02 AC3), а `compare` — как это отразилось на находках. Связка «diff версий
+ diff результатов» = мониторинг деградации между релизами.

## 5. CLI

```
morok regress export --finding <id>        # находка → тест
morok regress run --set <набор> --profile p@v
morok regress compare --before runs/<a> --after runs/<b>
```

## 6. Модули и интерфейсы

```
reporting/regression.py   # compare (до/после и A/B), RegressionDiff
```

```python
@dataclass
class RegressionDiff:
    per_attack: dict[str, str]     # id → перестала/осталась/появилась
    asr_before: float; asr_after: float
    smoke_ok: bool
def compare(before: RunResult, after: RunResult) -> RegressionDiff: ...
```

## 7. Трассируемость (E8 → US)

| Механизм | US |
|---|---|
| Находка → тест, тот же критерий, отдельный результат, набор | US-28 |
| Сравнение до/после, что закрылось/осталось/появилось, smoke, неизменность исходного | US-29 |
| A/B по режимам той же операцией | Ядро §6 |
