# Проверка гипотез, риски и план до финала

## Предварительные критерии успеха

| Критерий | Текущее состояние |
|---|---|
| Инструмент запускает атаку одной командой | Готово |
| Успех подтверждается по состоянию или tool call | Готово для BAC |
| ASR считается по нескольким попыткам | Готово: 4/4, ASR 100% |
| Артефакты запуска воспроизводимы и не содержат секретов | Покрыто тестами |
| Есть cross-session и cross-user атака через память | Сценарий готов, live-результат не подтверждён |
| Видна сквозная трасса runner и target | Код готов, live-smoke не проведён |
| Защита снижает ASR без поломки обычного сценария | Не проверено |
| Автоматизация сокращает время ручной проверки | Не измерено |

Техническая база прошла 77 автоматических тестов. Завершённый live-прогон adaptive BAC дал 4 доказанные атаки из 4 на намеренно уязвимом стенде.

## Главные допущения

- Команда агента может предоставить API, архитектуру, роли и описание инструментов.
- Для критичных эффектов доступен хотя бы один проверяемый источник: память, журнал инструмента, БД или трасса.
- Локальная LLM сможет создавать достаточно разные сценарии. Это нужно сравнить с фиксированной библиотекой.
- Найденный сценарий можно повторить после обновления агента.

## Риски

| Риск | Что делаем сейчас |
|---|---|
| Высокая привязка к учебному стенду | Отделили pipeline от State Tracer; следующий шаг — интерфейс адаптера |
| Ложный успех по тексту ответа | Verdict строится по состоянию и фактическим tool calls |
| Маленькая выборка и завышенный ASR | Показываем размер выборки и не обобщаем 4/4 на другие системы |
| Memory poisoning зависит от поведения модели | Сохраняем отдельные проверки записи, извлечения и действия |
| Langfuse может быть недоступен | Трассировка fail-open; локальные evidence остаются источником истины |
| Тест может затронуть реальные данные | Работаем только на авторизованном изолированном стенде с синтетическими данными |

## Проверки до 7 сентября

1. Запустить `mem-policy-conformant` и `poison-to-tool-chain` минимум по три раза.
2. Для каждого шага сохранить memory snapshot, tool call и assertion.
3. Повторить BAC-набор в `protected` режиме и сравнить ASR.
4. Проверить обычный запрос своего портфеля, чтобы защита не ломала полезный сценарий.
5. Поднять Langfuse и сохранить одну полную трассу.
6. Замерить время настройки и запуска одного теста.
7. Показать отчёт одному представителю целевой роли и записать замечания.

## Решение на промежуточной точке

Продолжаем с узким state-based MVP. До финала не расширяем интерфейс и не добавляем новые классы атак, пока не подтверждена цепочка через память и сравнение с защищённым режимом.
