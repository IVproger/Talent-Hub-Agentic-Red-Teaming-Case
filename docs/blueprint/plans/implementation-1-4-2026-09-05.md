# Реализация пунктов 1–4 — заметки для участников

Задача: надёжный единый pipeline, миграция CLI/UI, живое подтверждение цепочек,
подготовка атак из описания цели. Основная ветка репозитория — `main`.

## Этап 1: надёжность ядра

- `run_scenario` принимает необязательные `on_attempt` и `should_stop`.
  Callback вызывается после каждой попытки; остановка между попытками не
  разрушает выполняемую цепочку. Ctrl+C сохраняет также доступные данные
  незавершённой попытки, с verdict `error`.
- `run_campaign` делает checkpoint после каждой попытки: evidence, transcript,
  findings, report, status. При Ctrl+C сохраняет `status=interrupted` и повторно поднимает KeyboardInterrupt
  (контракт общей реализации CLI/UI сохранён); ошибка оркестрации даёт `failed`.
- Предикат `optional: true` сохраняется в evidence, но не блокирует verdict
  и не требует своего источника в capability-гейте. Обязательные ошибки
  evidence по-прежнему дают `error`.
- `reset_policy=per_step` сбрасывает состояние перед каждым шагом;
  `per_scenario` — перед каждой попыткой цепочки; `none` — без сброса.
- Основной ASR: доля сценариев с хотя бы одной `proven` среди сценариев,
  у которых есть хотя бы одна неошибочная попытка, **отдельно по режимам**.
  `indirect` входит в знаменатель. Ошибки и `expect=pass` исключены.
  `asr_by_mode` — основной разрез; общий `asr_percent` объединяет пары
  сценарий/режим, `attempt_asr_percent` — дополнительная метрика по попыткам.
- `PlannedScenario` получает `expect` (`attack_success`/`pass`) и `remediation`.
  Штатные проверки публикуются отдельно в `findings.smoke`.
- Секреты удаляются из сохраняемых строк; полный несекретный evidence
  сохраняется. Рекомендации отчёта имеют детерминированный fallback по предикату.

Проверка этапа: 345 тестов полного набора после интеграции с командной main
`6d1d42a`. Сохранены общий RunEvent и fail-open обработка событий/телеметрии.
