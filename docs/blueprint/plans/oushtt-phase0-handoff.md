## Контракты для интеграции

| Модуль | Публичные типы |
|---|---|
| `agentic_redteam.profile.schema` | `TargetProfile`, `ToolDecl`, `MemoryDecl`, `Boundary` |
| `agentic_redteam.adapters.base` | `Principal`, `AdapterFeature`, `UnsupportedFeature`, `TargetUnavailable`, `TargetSession`, `TargetAdapter` |
| `agentic_redteam.evidence.base` | `EvidenceKind`, `Marker`, `Observation`, `CalibrationResult`, `EvidenceProvider` |
| `agentic_redteam.errors` | `PipelineConfigurationError` |

Сигнатуры соответствуют §1.1, §3.1, §4.1 спецификации. Протоколы поддерживают
структурную проверку `isinstance`; наследоваться от них реализациям необязательно.
Проверка `isinstance` подтверждает наличие членов, но не типы аргументов или поведение.

Уточнения мест, которые не были полностью определены в плане:

- `CalibrationResult(ok: bool, message: str = "")` — frozen dataclass;
  `CalibrationResult(True)` означает успешную проверку, `False` с пояснением — провал.
  Идентификатор провайдера добавляет вызывающий bundle при формировании `CheckResult`.
- `TargetAdapter.preflight()` возвращает существующие `doctor.CheckResult`
  (`name`, `ok`, `message`, `blocking=True`). Импорт в протоколе только для проверки типов;
  выполнение нового пакета не загружает старые `doctor`/`pipeline`.
- `PipelineConfigurationError` вынесен из удаляемого в задаче 4.4 `pipeline.py`
  в `errors.py`. Старый импорт из `pipeline` продолжает возвращать тот же класс.
  Это единственная правка существующего production-модуля в этой части Фазы 0.
- YAML хранит инструменты и память в `surface`, модель — в `profile.tools` /
  `profile.memory`. Реестр задачи 1.2 должен восстановить `surface` при сериализации,
  а для `Boundary` — вложенный `principal: {attribute, type}`.
- Отсутствующие секции получают независимые пустые списки/словари;
  `modes == {}`, `attribution == "serialized"`. Тип принципала границы по умолчанию
  `string` (как в сокращённом примере DVAA); отсутствующие аргументы инструмента — `[]`.
- Frozen запрещает присваивание полей dataclass, но вложенные списки/словари сохраняют
  типы из плана. Загрузчик не обращается к цели и не разрешает секреты из окружения.
- Конфигурации провайдеров остаются декларативными. Проверка схемы не означает,
  что произвольный названный провайдер уже реализован или доступен.

Общий `tests/fakes.py` отсутствовал на момент реализации и не создавался: это зона
задачи 0.0. Тесты адаптера и evidence содержат локальные сценарные реализации
протоколов; после получения общих фейков нужна дополнительная проверка совместимости.
