# Отправная точка: что есть, что сломано, чего не хватает

Выводы по итогам съёмки живого приложения. Всё проверено на работающем
интерфейсе (Streamlit 1.63.0), а не выведено из кода.

## 1. Сломанный CSS: шесть правил не применяются

Оформление написано под структуру DOM старых версий Streamlit. В текущей
версии атрибут `data-baseweb` удалён из фронтенда полностью (0 узлов на
странице), а часть `data-testid` переименована. Замеры —
[`selector-health.json`](../03-tokens/selector-health.json) и
[`computed-styles.json`](../03-tokens/computed-styles.json).

| Правило в `app.py` | Совпадений | Что из-за этого видно |
| --- | --- | --- |
| `.stFormSubmitButton>button[kind="primary"]` | 0 — реальный `kind` равен `primaryFormSubmit` | **Главная кнопка «ЗАПУСТИТЬ» никогда не заливается чёрным.** В активном состоянии она неотличима от «ПРОВЕРИТЬ» |
| `[data-baseweb="select"]>div` | 0 | Все 4 селекта остались скруглёнными и со своим фоном рядом с квадратными кнопками — [кадр 01](../01-screens/01-default-desktop.png) |
| `[data-baseweb="tab-list"]` | 0 | Не применились `border-bottom` и `gap:1.1rem` между вкладками |
| `[data-baseweb="tab"]` | 0 | Не применились `padding:.7rem 0` и `font-size:.68rem` |
| `[data-testid="stProgressBar"]>div>div` | 0 — реальные id `stProgress` / `stProgressBarTrack` | Прогресс-бар красится темой, а не CSS. Совпало по цвету случайно |
| `border-radius:0` в целом | частично | На странице живут скругления 2px, 4px и 8px — заявленной «нулевой» геометрии нет |

Работают, вопреки ожиданию: `[aria-selected="true"][role="tab"]`
(подчёркивание активной вкладки) и `[data-testid="stExpandSidebarButton"]` —
последний применяется в состоянии со свёрнутым сайдбаром
([кадр 35](../01-screens/35-sidebar-collapsed.png)), там кнопка честно
позиционируется `fixed` в 12px от края.

Практический вывод: **новый UI нельзя строить на CSS-инъекции поверх чужого
DOM.** Она уже сломалась один раз молча и сломается снова на следующем
обновлении Streamlit.

## 2. Типографика: 16 размеров, девять из них — мелкий текст

В CSS 16 разных `font-size` от `.59rem` до `1.5rem`, из них девять лежат
между `.59rem` и `.72rem` — это 9.4–11.5 px. На живой странице замерено
21 разное значение размера шрифта, включая 8 px.

Основной текст описания сценария — `.78rem` (12.5 px). Подписи метрик,
строки preflight, мета сценария, живой лог — 9–11 px. Шкалы нет: размеры
подбирались под каждый блок отдельно.

Шрифт один на всё, включая заголовки и интерфейс: JetBrains Mono, подключён
с `fonts.googleapis.com` (внешняя зависимость в on-prem-продукте). Иерархия
строится только размером и весом, потому что второго шрифта нет.

## 3. Цвет не работает как сигнал

Палитра — пять переменных: `--ink #11110f`, `--paper #f4f4ef`,
`--surface #e9e9e4`, `--line #a9a9a1`, `--muted #5c5c57`. Ни одного
акцентного цвета.

Следствия, видимые на скриншотах:

- `info`, `success`, `warning`, `error` — один и тот же серый прямоугольник,
  иконки принудительно обесцвечены ([кадр 34](../01-screens/34-component-alerts.png));
- `PASS` и `FAIL` в preflight отличаются только текстом
  ([кадр 12](../01-screens/12-component-check-rows.png));
- `COMPROMISED` и `NOT PROVEN` — тоже только текстом
  ([19](../01-screens/19-component-result-summary.png) против
  [17b](../01-screens/17b-component-result-summary-incomplete.png));
- `PROVEN` / `NOT_PROVEN` в таблице попыток не выделены никак.

Для продукта, единственный результат которого — «взломали или нет»,
это главная потеря. На демо зритель не считывает вердикт с экрана,
его приходится проговаривать голосом.

## 4. Дефекты, которые видно на кадрах

**Заголовок не соответствует результату.** `_render_scenario_summary()`
рисует сценарий, выбранный в сайдбаре, а вкладки под ним — загруженный из
истории прогон. На [кадре 18](../01-screens/18-result-tab-outcome-desktop.png)
сверху «Memory poisoning via Policy-Conformant Fact Injection», снизу —
результат `generated-bac`. Разные вещи выглядят как одна.

**Запрос и ответ обрезаются.** В шагах трейса `st.code` в двух колонках
режет строку по ширине без переноса и без горизонтального скролла
([кадр 21](../01-screens/21-result-tab-trace-tall.png)) — payload атаки,
то есть самое содержательное, прочитать нельзя.

**Ошибки складываются стопкой.** Две-три одинаковые серые плашки подряд
([кадр 14](../01-screens/14-form-validation-error.png)); что чинить первым,
непонятно.

**Форма не блокируется во время прогона.** `run_in_progress` есть в
состоянии, но поля и кнопки остаются активными.

**Сайдбар не сжимается.** `min-width:360px; max-width:360px`, брейкпоинтов
нет. На 1024 px таблицы теряют правые колонки
([кадр 28](../01-screens/28-narrow-1024.png)).

**Отчёт выпадает из оформления.** `report.md` рендерится дефолтным markdown
Streamlit ([кадр 25](../01-screens/25-result-tab-report-tall.png)) — другие
размеры, другие отступы, чем на остальной странице.

**Пустая область до первого прогона.** Две трети экрана заняты одной серой
плашкой ([кадр 03](../01-screens/03-main-empty-state.png)).

Сверено с

| Шаг целевого пути | Что есть сейчас |

| Ввод контекста цели: архитектура, техдоки, API и MCP-контракты, endpoints | Два textarea и два загрузчика внутри свёрнутого expander в форме запуска. API/MCP-контрактов и endpoints нет |

Плюс сквозное: **бренд MOROK в интерфейсе не появляется ни разу** — ни в
заголовке, ни в шапке, ни во вкладке браузера. Везде `Agentic Red Team`.

## 6. Что стоит сохранить

Не всё нужно выбрасывать. В текущем UI есть решения, которые работают:

- **`.result-summary`** — вердикт крупно, четыре метрики в ряд, полоса доли.
  Единственный блок с внятной иерархией;
- **`.step-line`** — цепочка `generate → probe → observe → verdict` одной
  строкой, сразу объясняет механику сценария;
- **`.trace-rail`** — компактная рейка шагов с числом tool call и дельтой
  памяти;
- **read-only блок моделей** — честно показывает, что конфигурация приходит
  из YAML и в UI не переопределяется. Это продуктовая позиция, а не
  ограничение;
- **дисциплина «сначала preflight, потом запуск»** с fingerprint
  конфигурации — правильная механика, ей не хватает только визуального веса;
- **общий аскетизм** — отсутствие теней, градиентов и иконок-украшений
  соответствует «строгому деловому решению» из брифа. Проблема не в
  сдержанности, а в том, что при ней не осталось средств для акцента.

## 7. Ограничения платформы, которые упрутся в редизайн

- в Streamlit нет своего роутинга без `st.Page`/`st.navigation`; многошаговый
  путь из концепции придётся строить явным state machine или переходом
  на многостраничное приложение;
- любое взаимодействие — полный rerun скрипта; анимации переходов и
  оптимистичные состояния недостижимы без своего компонента;
- оформление чужих виджетов возможно только CSS-инъекцией по `data-testid`,
  и это уже подвело (раздел 1). Устойчивый путь — собирать ключевые блоки
  своим HTML, как сейчас сделано с восемью компонентами;
- `unsafe_allow_html=True` уже используется, экранирование через `_safe()`
  есть — расширять этот подход безопасно при том же правиле.
