# Атрибуция evidence по шагам — 2026-09-05

Исполнитель: oushtt. Дополнительная интеграционная задача после живого BAC;
затрагивает runner/orchestrator/catalog из потока dseredkin по указанию пользователя.

## Ошибка и результат

Раньше runner собирал одно окно evidence на цепочку и сравнивал все вызовы
с актором сценария. В цепочке `inject(A) → finalize(A) → activate(B)` чтение
клиентом B собственных данных могло дать ложный `proven`, а вызов на inject
мог засчитаться как эффект activate.

Теперь каждый шаг выполняется как `mark → действие → collect_facts`. Роль
разрешается адаптером; сравнение использует `session.principal.value` именно
этого шага. Шаги одной роли сохраняют общую сессию. Сброс памяти остаётся перед
попыткой, поэтому финализация и последующая активация используют внедрённую память.

## Семантика для команды

- `at` выбирает facts и principal указанного шага для любого предиката.
- `cross_session_effect` без `at` выбирает `activate`; `inject` должен идти раньше.
- Без селектора memory/callback/principal-equals используют сумму фактов цепочки.
  Проверки mismatch/isolation сравнивают каждый шаг с его собственным principal;
  успех — нарушение хотя бы на одном шаге.
- `response_contains` с `at` использует только ответ этого шага. Finalize без
  текстового ответа не заимствует ответ соседнего шага. Без `at` берётся последний
  текстовый ответ, как раньше.
- Неизвестные ссылки, повторные имена и противоречащие друг другу `at/activate`
  отклоняются до воздействия на цель. Старый прямой вызов `run_scenario` без
  явных steps сохраняет произвольные метки `at` для единственного неявного шага;
  YAML-каталог всегда проверяет ссылки строго.
- Ошибка шага/источника даёт `error`, без положительных outcomes. Evidence уже
  завершённых шагов сохраняется; незавершённый шаг имеет ошибку и `facts: null`.

## Артефакты и совместимость

Новый `campaign.runner.StepEvidence` хранит name, role, principal, session_id,
facts, observations, response и error. `AttemptResult.steps` переносит их
в `evidence-NNNN.json.steps`; верхние facts/observations оставлены как агрегат
для совместимости. Transcript содержит метаданные шагов и полноту evidence,
а отчёт перечисляет фактические роли и principals. Прежние прогоны не меняются.

Замороженные Facts/ObservedToolCall, TargetAdapter и EvidenceBundle не менялись.
На стороне фейков нужно выдавать Facts **на каждый шаг**; тестовые сценарии
с одним общим Facts на несколько шагов необходимо обновить. Само окно лога
остаётся последовательным: нужен эксклюзивный прогон без чужих запросов к цели.
Для асинхронных источников по-прежнему требуется подтверждённая готовность данных.

## Проверка

318 тестов прошли на Python 3.14. Регрессии покрывают ложное нарушение при чтении
своих данных, перенос вызова между шагами, фактического актора активации,
`cross_session_effect`, память финализации, неизвестные ссылки, текст ответа,
сохранение частичных evidence и файловую отчётность.

Живой `poison-to-tool-chain` в vulnerable/protected пока не выполнялся на этом
изменении. Результат будет добавлен отдельным коммитом после прогона.
